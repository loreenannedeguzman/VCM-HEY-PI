# Experiment History

This document synthesizes the experiments that materially shaped E50. It is not a complete raw log and does not replace the final results section.

| Experiment / phase | Purpose | Evidence / finding | Engineering consequence |
|---|---|---|---|
| Early baseline work | Prove that local audio features and simple classifiers could support the command task. | The historical logs record baseline model work before the final command system. [EH-01] [EH-02] | Established the pipeline before the project depended on Raspberry Pi deployment behavior. |
| E21 CNN baseline | Evaluate an early CNN command recognizer. | The decision record identifies E21 as an early CNN baseline with useful performance but accepted-command precision risk. [EH-03] | The project moved beyond raw validation accuracy and began treating confidence-filtered action safety as a separate criterion. |
| E23 targeted real-microphone light adaptation | Exercise the command model under real-microphone light-command conditions. | The records state that E23 improved held-out real-microphone light behavior relative to E21, but lowered official validation macro-F1; E21 remained the general validation baseline while E23 became a deployment-focused candidate for further microphone testing. [EH-01] [EH-02] [EH-04] | The project treated real-device evidence as necessary, not optional, and learned that targeted deployment adaptation can trade off against broader validation performance. |
| Phase C diagnostic baseline | Preserve a frozen diagnostic comparison point during recovery work. | The decision record describes Phase C as a frozen diagnostic baseline rather than a final promoted system. [EH-03] | Later candidates were compared against controlled evidence instead of replacing the baseline informally. |
| E40 confidence policy | Separate classification from execution by accepting or rejecting predictions using frozen confidence rules. | The decision and examination records treat E40 as a safety guardrail that can reject uncertain or risky predictions before action routing. [EH-03] [EH-04] | E50 evaluation included accepted-correct, accepted-wrong, and safe-rejection behavior rather than raw accuracy only. |
| E41 functional recovery | Establish a stronger command-recognition candidate after deployment mismatch and recovery work. | The decision record kept E41 as the current evidence-supported candidate after E43/E44/E45 did not supersede it. [EH-03] | E41 became the reference point for later controlled comparisons, recovery diagnosis, and architecture/data decisions. |
| E43 / E44 targeted recovery | Attempt targeted repairs for observed command failures. | E43 reduced some wrong-accept regressions but remained below E41 and failed the intended COLOR recovery set; E44 degraded holdout behavior and still failed the intended recovery objective. [EH-03] | These experiments were preserved as evidence but not promoted. |
| E45 / E46 / E47 follow-up recovery | Test whether further fine-tuning or targeted ablations could improve the E41 path. | The decision record states that these candidates introduced regressions or increased accepted-wrong outcomes under frozen E40. [EH-03] | E41 remained frozen while the project narrowed the conditions under which any future candidate could be promoted. |
| E48 architecture investigation | Explore whether a controlled architecture experiment could address classifier limitations. | Phase AJ/AL records describe a controlled temporal-context architecture hypothesis, while later records emphasize dataset-control requirements and promotion caution. [EH-03] [EH-04] | The project recognized that model changes needed controlled data boundaries and regression analysis before promotion. |
| E49 hybrid dataset experiment | Test a hybrid-data command model direction. | The examination notes state that E49 improved some independent examples but produced accepted-wrong cases and current95 regressions. [EH-04] | E49 informed final data/model design but was not the final command system. |
| E37 wake gate | Separate wake detection from command classification. | E37 became the wake-gate model used by the final system. The recovered Pi audit establishes 99 project-specific Hey Pi wake-stage recordings, including 50 `WAKE` / `hey pi`, 64 adaptation-designated rows, and 35 holdout-designated rows. [EH-05] | The integrated stack uses a wake-gated architecture: wake detection opens a command window, then the E50 command model handles command labels. |
| E50 revised command model | Build the final revised-vocabulary command model. | The examination notes state that E50 and E51 were trained/evaluated using a controlled 16,100-row hybrid training manifest and that E50 was selected as the better final balance for command-classifier role. [EH-04] | E50 became the frozen final command CNN for the 19-command delivery system. |
| E51 fresh-initialization baseline | Provide a comparable baseline against E50. | The examination notes describe E51 as safer in some broader Dataset2/combined testing but weaker on protected-compatible current95 and Phase AV-compatible performance. [EH-04] | E51 remained comparison evidence, not the final E50 command model. |
| Final Pi benchmark / Item 16 | Measure the frozen integrated stack near final delivery. | The logs identify Item 16 as benchmark recording/reporting only and state that E37, E50, E40, thresholds, routing, response assets, GUI behavior, runtime behavior, microphone configuration, and audio configuration were unchanged. [EH-01] [EH-04] | The benchmark supported the final freeze and reported both strengths and limitations without reopening training or threshold tuning. |

## E37 Training-Lineage Qualification

The recovered E37 audit strengthens the wake-gate provenance record by proving that the project-specific Hey Pi recording set existed and by documenting its manifest, labels, adaptation/holdout split designations, 4-second duration, 16 kHz sample rate, and `plughw:2,0` input device. [EH-05]

The recovered evidence does not establish E37 training-row membership. This includes the 99-row recording set, the 50 `WAKE` recordings, and the 64 adaptation-designated recordings.

The exact final E37 training subset, training manifest, epoch count, optimizer, validation metrics, augmentation count, speaker/recordist count, and complete row-to-checkpoint mapping remain unestablished in the recovered evidence. [EH-05]
